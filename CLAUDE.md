# Bandeiras

A static PWA, in Portuguese, for learning the countries of the world: their flags, where they lie on the map, and their capitals. It runs on GitHub Pages; the only backend is a Supabase project behind the Quiz ranking.

## The game

Three areas, picked by the hub selector: **Bandeiras**, **Mapas** and **Capitais**. Each shows the continent tabs plus Mundo, and each level card offers two modes:

- **Aprender** teaches. A round has 3 lives and awards a medal by lives left (gold 3, silver 2, bronze 1); after losing the last life the player may continue without a medal.
- **Quiz** asks every country of the level once, against the clock, and keeps best score, best time and completion, plus an online ranking.

Aprender has two engines, and a new Learn mode picks one of them:

- `Round` (`src/engine/round.ts`) drives Bandeiras: each flag is introduced through a choice question before any other format, and the round is won at a goal of right answers (`goalFor` in `src/engine/pool.ts`).
- `LadderRound` (`src/engine/ladderRound.ts`) drives Mapas and Capitais: every country climbs a ladder of formats (`MAP_LADDER`, `CAPITAL_LADDER`); a right answer climbs one step, a wrong one drops one, and the round is won when every country has topped the ladder. The first step of a ladder must be answerable with no knowledge of the subject, by bridging from something the player already learned elsewhere in the app.

Aprender is offered only where the hub card sets `learn`, because a ladder over a whole continent or Mundo runs to hundreds of answers. Every screen that navigates to `game`, `mapGame` or `capitalGame`, result screens and continent reports included, must stay inside those levels.

A typed answer that is a typo of the right name is refused with "Confira a grafia" and costs nothing; a name or capital of another country is wrong (`judgeTypedName`, `judgeTypedCapital` in `src/engine/answer.ts`).

## Layout

- `src/engine` holds the game rules and never touches the DOM.
- `src/ui` builds every screen with `el()` from `src/ui/dom.ts`, with no framework. `Screen` in `src/ui/navigation.ts` lists every screen and its parameters.
- A question format spans four places, and the type checker flags the ones you miss: the `Question` variant in `src/engine/question.ts`, the `Format` in the area's `*Formats.ts`, its branch in `grade`, and its case in `renderQuestion` (`src/ui/questions/render.ts`).
- `src/ui/map/map.ts` draws every map: shapes, paint states, focus framing and pinned points. Its projection per continent lives in `src/ui/map/projection.ts`.

## Data

All country data lives in `src/data`, keyed by `iso2`:

- `countries.json` is the source of every country: name, aliases, continent, status and flag `tier`. The tier sets the Bandeiras levels (Fácil, Médio, Difícil; Geral is all three).
- The Mapas pool is every sovereign state plus a short list of chosen territories: `map-excluded.json` lists what stays off the map, and `map-regions.json` splits each continent into the region levels.
- The Capitais pool of a continent is its Mapas pool minus `capitals-excluded.json`, split into Fácil, Médio and Difícil by `capital-levels.json`. `capitals.json` holds each capital with its aliases and coordinates.
- `similar-groups.json`, `similar-names.json` and `similar-capitals.json` feed the look-alike wrong options.
- `map-excluded.json`, `map-regions.json` and `capital-levels.json` are hand-kept lists whose contents are the owner's call: propose changes and have them reviewed before the merge.
- `map.topo.json` is generated by `npm run build:map` from Natural Earth and `map-excluded.json`: never edit it, and never read it into context.

## Player progress

Progress lives only in the player's `localStorage`, under keys prefixed `flags-quiz:`.
Changing the shape of a stored value means a new versioned key (as in `flags-quiz:quiz-records-v2`), which wipes that progress for every player: ask the owner first.
Changing which countries a level holds keeps the keys: medals and records earned on the old contents stay as they are.

## Ranking

The Quiz ranking calls three `security definer` RPC functions on Supabase with plain `fetch`; row level security blocks every direct access.
The committed `.env` holds `VITE_SUPABASE_URL` and `VITE_SUPABASE_PUBLISHABLE_KEY` on purpose: both ship in the public bundle, and `vite build` fails without them.
Migrations live in `supabase/migrations/`; `supabase db push` applies them to the production project, so run it only when the owner asks.

## Tests

- Gates: `npx vitest run` and `npx tsc --noEmit`. There is no linter. CI runs `npm test` and `npm run build`, which type-checks.
- Tests run in Node by default. A test that touches the DOM starts with `// @vitest-environment happy-dom`.
- happy-dom does no layout: map tests stub `getBoundingClientRect` and `getScreenCTM` on the SVG, as `src/ui/map/map.test.ts` does.
- A change a player sees gets played in the browser on a dev server of its own (`npx vite --port <free port>`), at 390px. The dev server serves from `/`; the build and `vite preview` serve from `/flags-quiz/`.

## Branches and deploy

Every push to `main` deploys to production on GitHub Pages (`.github/workflows/deploy.yml`).
Work on a feature branch, fast-forward it into `main` and push only when the owner approves that merge.

## Language

Player-facing copy is Portuguese (Brazil). Code, comments, identifiers, commits and specs stay English.

## Specs

Designs and plans live in `docs/specs/` as `YYYY-MM-DD-<topic>-design.md` and `YYYY-MM-DD-<topic>-plan.md`. A spec records a decision at its date; when it disagrees with the code, the code wins.
